Axiom Dashboard Queries — Serenity Mental Health API
=====================================================

Datasets (from deployment/.env):
  - Traces  → serenity-traces   (use APL — section below)
  - Metrics → serenity-metrics  (use MPL — primary section)
  - Logs    → serenity-logs     (use APL — section at bottom)
  - Service → serenity-mental-health-api

Note: Metrics panels MUST use MPL (not APL). Traces and logs use APL.
Histogram metrics (message length, request duration) need `bucket` — NOT `avg(value)`.
If a query returns empty, open serenity-metrics → Metrics browser and confirm the name.


PRIMARY METRICS (serenity-metrics) — MPL
----------------------------------------

Use these three for the assignment dashboard panels.

1. Intent distribution (NLP) — nlp.intent.classified  [Counter]
`serenity-metrics`:`nlp.intent.classified`
| group by `intent` using sum


2. Message length p50 / p95 (Data) — data.chat.message.length  [Histogram]
Try delta temporality first:
`serenity-metrics`:`data.chat.message.length`
| bucket to 5m using interpolate_delta_histogram(0.50, 0.95)

If empty, try cumulative:
`serenity-metrics`:`data.chat.message.length`
| bucket to 5m using interpolate_cumulative_histogram(rate, 0.50, 0.95)

Chat message count (how many /chat calls recorded):
`serenity-metrics`:`data.chat.message.length`
| where `axiom.histogram` == "count"
| align to 5m using sum


3. Request volume (Server) — http.server.request.count  [Counter]
`serenity-metrics`:`http.server.request.count`
| align to 5m using sum


4. Error rate (Server) — requests with status >= 400
`serenity-metrics`:`http.server.request.count`
| where `http.status_code` >= 400
| align to 5m using sum
| group by `http.status_code` using sum


5. Feedback votes (Data) — data.feedback.vote  [Counter]
`serenity-metrics`:`data.feedback.vote`
| group by `vote` using sum


6. Request count by route
`serenity-metrics`:`http.server.request.count`
| group by `http.route` using sum


7. Request duration p95 by route (Histogram)
`serenity-metrics`:`http.server.request.duration`
| bucket by `http.route` to 5m using interpolate_delta_histogram(0.95)


8. Active requests (live load)  [UpDownCounter / Gauge]
`serenity-metrics`:`http.server.active_requests`
| align to 1m using max


9. Process uptime (seconds)  [Observable gauge]
`serenity-metrics`:`server.process.uptime`
| align to 1m using max


TRACES DATASET (serenity-traces) — APL
--------------------------------------

11. Total requests over time
['serenity-traces']
| where ['service.name'] == "serenity-mental-health-api"
| where ['attributes.http.route'] != "/health"
| summarize count() by bin(_time, 5m)


12. Requests per endpoint
['serenity-traces']
| where ['service.name'] == "serenity-mental-health-api"
| where isnotnull(['attributes.http.route'])
| summarize count() by ['attributes.http.route']
| order by count_ desc


13. Average latency per endpoint (ms)
['serenity-traces']
| where ['service.name'] == "serenity-mental-health-api"
| where isnotnull(['attributes.http.route'])
| summarize avg(duration) by ['attributes.http.route']
| extend avg_ms = avg_duration * 1000
| order by avg_ms desc


14. /chat endpoint latency over time
['serenity-traces']
| where ['service.name'] == "serenity-mental-health-api"
| where ['attributes.http.route'] == "/chat"
| summarize avg(duration), percentile(duration, 95) by bin(_time, 5m)
| extend avg_ms = avg_duration * 1000, p95_ms = percentile_duration_95 * 1000


15. Outbound calls (LLM / Qdrant via httpx)
['serenity-traces']
| where ['service.name'] == "serenity-mental-health-api"
| where name contains "HTTP" or name contains "httpx"
| summarize count(), avg(duration) by name
| extend avg_ms = avg_duration * 1000
| order by count_ desc


LOGS DATASET (serenity-logs) — APL
----------------------------------

16. Error logs over time
['serenity-logs']
| where severity_text == "ERROR" or level == "ERROR"
| summarize count() by bin(_time, 5m)


17. Chat pipeline logs
['serenity-logs']
| where body contains "Chat request" or body contains "Intent:" or body contains "Emotion:"
| project _time, body, trace_id
| order by _time desc
| take 100

TROUBLESHOOTING — panel empty or MPL error
------------------------------------------

1. Dataset: use **serenity-metrics** (Metrics type), not serenity-traces.
2. Generate data: `data.chat.message.length` is only recorded on **POST /chat**.
3. Wait ~15–30 seconds after requests (OTLP export interval is 15s).
4. Histogram query must be on ONE line — do not merge two queries:
   `| bucket to 5m using interpolate_delta_histogram(0.50, 0.95)`
5. If delta histogram is empty, try cumulative (query #2 alternate in file above).
6. Tag names may be `intent`, `http.route` — check Metrics browser in Axiom.
